# ADR-0001: SDK 调试开关对原生日志级别采用"只升不降"

## 状态

已接受(2026-10-07)

## 背景

SDK 需要一个 `configure({ debug: true })` 调试开关,端到端生效:SDK console 日志 + 原生插件文件日志同时进入 debug 级。但原生插件是**全机共享的单例进程**——多个页面、多路流共用一套全局日志级别(tracing 的 EnvFilter)。一个页面关闭或刷新后,其他页面仍在使用这个进程。

候选方案:

1. **引用计数降级**: 记录开启 debug 的连接数,最后一个断开时降回 config.toml 级别。
2. **持久化**: SDK 改写 config.toml,重启后仍生效。
3. **只升不降**: hello 携带 debug 标志,连接期间提升进程级别;不降回,进程重启自然恢复。

## 决策

选 **3(只升不降)**。技术实现:EnvFilter 经 `reload::Layer` 包装,handle 存于 `plugin_server::logging`,hello 处理器调用 `raise_to("debug")`。

理由:

- 调试开关的使用场景就是"有人在排障"。排障期间机器多打日志无害;排障结束忘记关,也只是日志稍多,不丢数据、不影响播放。
- 方案 1 为罕见场景(多页面同时连接且只有部分开 debug)引入连接跟踪 + 计数 + 竞态处理,复杂度配不上收益。
- 方案 2 把临时排障动作变成持久状态,忘了关会永久拖慢用户机器,更糟。

## 后果

- 先开 debug 的页面"说了算":debug 开启后,所有页面(包括没开 debug 的)的流量都以 debug 级别记录,直到进程重启。
- `raise_to` 有防护:目标级别不高于(更啰嗦于)当前级别时不动作,即 `RUST_LOG=trace` 不会被页面降到 debug。
- 旧版插件不认识 hello 的 debug 字段,静默忽略(降级为仅 SDK console 日志),协议版本不 bump。
